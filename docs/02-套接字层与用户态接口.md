## 0. 本章定位

- **协议栈层次**：用户在 socket 上做的每一次 `read/write/send/recv`，都要经过
  「VFS file 层 → socket 抽象层（`net/socket.c`）→ 协议族抽象（`struct proto_ops`）
  → 具体传输层（`struct proto`，如 `tcp_prot`）」这一条链路才会碰到 TCP/UDP。
  本章讲的正是这条链路，以及内核为了让 TCP/UDP 能被复用而设计的**双层抽象**
  （`struct socket` / `struct sock`）。
- **前置章节**：第 01 章（网络子系统总览、sk_buff 与设备层全貌）。若还没读，至少
  需要知道 `struct sk_buff` 是内核里网络数据的载体。
- **学完能回答什么问题**：
  1. `fd` 是怎么一路找到 `struct sock` 的？为什么 `struct socket` 和 `struct sock`
     要分成两层？
  2. `socket()` 之后内核到底分配了哪些对象？`sk_alloc()` 和 `sock_init_data()` 各做什么？
  3. `bind()` 的端口是从哪里来的？`connect()` 时内核怎么选本地端口？
  4. 我 `setsockopt(SO_RCVBUF, 65536)`，为什么 `getsockopt` 读出 131072？
  5. `write()` 一次 1 MB，内核会分成几个 skb？数据被拷贝了几次？
  6. `epoll` 是怎么被 TCP 数据到达唤醒的？`sk_data_ready` 和 `ep_poll_callback`
     是什么关系？
  7. `SO_REUSEADDR` 和 `SO_REUSEPORT` 在内核里落在哪个字段、被谁判断？
  8. `sendfile`/`splice`/`MSG_ZEROCOPY` 分别省掉了哪一次拷贝？

## 1. 核心概念与设计权衡

### 1.1 为什么要有 `struct socket` 和 `struct sock` 两层

内核面对两类完全不同的需求：

| 需求 | 关心什么 | 谁来表达 |
| --- | --- | --- |
| 通用文件语义 | `open/close/read/write/ioctl/poll/mmap`、`f_op`、`inode` | `struct socket` + `socket_file_ops` |
| 协议实现语义 | 序列号、窗口、重传定时器、路由、内存记账 | `struct sock`（及其子类 `struct tcp_sock`、`struct udp_sock`、`struct inet_timewait_sock`） |

如果只有一层，那么「TCP 的序列号」和「VFS 的 `f_pos`」会挤在同一个结构体里，
既污染 VFS 又让 AF_UNIX/AF_NETLINK 这些非 IP 协议背负无用的字段。
于是内核把两者拆开，用 `struct socket` 做**协议无关的门面**，
用 `struct sock` 做**协议相关的内核控制块**，中间通过 `struct proto_ops`（门面 → 协议）
和 `struct proto`（协议内部的操作集）连接。

代价是：每次系统调用要跨两层间接调用（`sock->ops->sendmsg` → `sk->sk_prot->sendmsg`），
多了一次指针跳转，换来的是 AF_INET/AF_INET6/AF_UNIX/AF_VSOCK 共用同一套 syscall 实现。

### 1.2 `proto_ops` 与 `proto` 的分工

- `struct proto_ops`（`include/linux/net.h`）：由**地址族**决定，一个地址族一份。
  AF_INET 用 `inet_stream_ops` / `inet_dgram_ops` / `inet_sockraw_ops`，
  定义在 `net/ipv4/af_inet.c`。它面向「socket 层」的通用动作：
  `bind/connect/accept/listen/sendmsg/recvmsg/poll/ioctl/getsockopt/setsockopt/splice_read`。
- `struct proto`（`include/net/sock.h`）：由**协议**决定，一个传输协议一份，
  如 `tcp_prot`（`net/ipv4/tcp_ipv4.c`）、`udp_prot`（`net/ipv4/udp.c`）、`raw_prot`。
  它面向「sock 层」的协议动作：`close/connect/disconnect/accept/ioctl/init/
  destroy/shutdown/setsockopt/getsockopt/sendmsg/recvmsg/backlog_rcv/release_cb/
  hash/unhash/get_port/enter_memory_pressure/memory_allocated` 等。

`inet_stream_ops.sendmsg` 的实现 `inet_sendmsg()` 做的事就是拿到 `sk->sk_prot`
再转发一次——这就是「两层抽象」在代码里的具体形态。

### 1.3 几个关键权衡

- **线性区 vs frags（分片页）**：小包用「线性数据区」（`skb->head`/`data`），
  大包用「frags 数组」引用用户页（`skb_shared_info.frags`）。前者拷贝一次但内联紧凑，
  后者可以零拷贝但需要 scatter-gather 支持。
- **自动调优 vs 显式 set**：`SO_RCVBUF` 一旦被显式设置，内核就打上
  `SOCK_RCVBUF_LOCK` 标记，**关闭该 socket 的接收窗口自动调优**；
  未设置时接收缓冲会跟随 `net.ipv4.tcp_rmem` 的区间自动伸缩（`tcp_moderate_rcvbuf`）。
- **加倍语义**：内核内部记账（`sk_rcvbuf`）含「内核自用开销」，所以对外
  `getsockopt` 呈现时会除 2。这不是 bug，是为了兼容历史行为而刻意保留的 ABI 约定。
- **轮询 vs 回调**：socket 的内存回收既可能在「分配时同步触发」（`sk_mem_reclaim`），
  也可能被推迟到「下一次分配失败时」（`__sk_mem_reclaim`），
  这是为了避免在软中断里做昂贵的内存回收。

## 2. 关键内核数据结构

### 2.1 `struct socket`（`include/linux/net.h`）

```c
struct socket {
	socket_state		state;
	short			type;
	unsigned long		flags;
	struct file		*file;
	struct sock		*sk;
	const struct proto_ops	*ops;	/* IPV6_ADDRFORM / MPTCP 会替换 */
	struct socket_wq	wq;
};
```

- `state`：`SS_FREE/SS_UNCONNECTED/SS_CONNECTING/SS_CONNECTED/SS_DISCONNECTING`
  （`include/linux/net.h` 的 `enum socket_state`）。注意它**不是** TCP 状态机，
  TCP 状态在 `sk->sk_state` 里。
- `ops`：指向地址族操作集，如 `inet_stream_ops`。
- `wq`：`struct socket_wq { wait_queue_head_t wait; struct fasync_struct *fasync_list; ... }`，
  用户态 `poll/epoll` 等待的地方。**注意**：内核里还有 `sk->sk_wq` 指向同一个 `socket_wq`
  （`sock_init_data()` 里 `sk->sk_wq = &sock->wq`），因为协议层没有 `struct socket` 可用。
- 这个结构体**没有** `f_pos`、没有引用计数：它挂在 `file->private_data` 上，
  生命周期由 `file` 的引用计数保证。

与内存记账相关的内联函数（`include/net/sock.h`）：

```c
static inline void sk_mem_charge(struct sock *sk, int size)
{
	if (!sk_has_account(sk))
		return;
	sk_forward_alloc_add(sk, -size);   /* 向前分配余量减少 */
}

static inline void sk_mem_uncharge(struct sock *sk, int size)
{
	if (!sk_has_account(sk))
		return;
	sk_forward_alloc_add(sk, size);
	sk_mem_reclaim(sk);                /* 释放触发回收 */
}

int __sk_mem_schedule(struct sock *sk, int size, int kind);   /* 真正的限额判断 */
void __sk_mem_reclaim(struct sock *sk, int amount);
static inline int sk_wmem_schedule(struct sock *sk, int size);
static inline int sk_rmem_schedule(struct sock *sk, struct sk_buff *skb, int size);

/* 等待队列：老代码里的 sk_sleep() 在 6.12 仍然存在，是 &sk->sk_wq->wait 的
 * 便捷访问器（BUILD_BUG_ON 保证 socket_wq.wait 是首成员）。
 * 新代码应直接使用 sk->sk_wq 或调用 wake_up 系列宏。 */
static inline wait_queue_head_t *sk_sleep(struct sock *sk)
{
	BUILD_BUG_ON(offsetof(struct socket_wq, wait) != 0);
	return &rcu_dereference_raw(sk->sk_wq)->wait;
}
```

**6.12 的重要变化：内存记账改成 per-CPU 计数器**。
`sk_memory_allocated_add()` / `sk_memory_allocated_sub()`
（`include/net/proto_memory.h`）不再直接改全局的
`proto->memory_allocated`，而是先加到 `proto->per_cpu_fw_alloc`（每 CPU 变量），
只有累计值超过 `net.core.sysctl_mem_pcpu_rsv`（`net_hotdata.sysctl_mem_pcpu_rsv`）
时才 `proto_memory_pcpu_drain()` 一次性合并进全局原子计数。
读取用 `sk_memory_allocated(sk)` → `proto_memory_allocated(sk->sk_prot)`。

> 实测含义：**单个连接的瞬时内存变化不会立刻反映到全局计数上**
> （要等 per-CPU 变量被 drain）。本 lab 的 `sockopt_probe` 就实测到
> 「推送 0.5 MB 前后 `/proc/net/sockstat` 的 `TCP: mem` 完全不变」，
> 这既有噪声量级的原因，也有这套 per-CPU 批处理记账的原因。
> 排查单连接内存请优先看 `ss -tme` 的 `rb`/`tb`。
`sk_has_account(sk)` 等价于「协议声明了 `memory_allocated` 且非 `SOCK_NOACCOUNT`」，
TCP/UDP 都参与记账，因此它们的用量会汇总到
`/proc/net/sockstat` 的 `TCP: mem` / `UDP: mem` 与 `/proc/net/protocols`。

## 3. 数据流与函数调用链

### 3.1 `fd` → `struct sock` 的四次解引用

```
用户态:  write(fd, buf, len)
   │
   ▼  VFS:  sys_write() → vfs_write() → fdget_pos() → struct fd { struct file * }
struct file  (每个 open/socket 一份)
   │  file->f_op == &socket_file_ops   （net/socket.c 里的 socket_file_ops）
   ▼  f_op->write_iter == sock_write_iter()
sock_write_iter(struct kiocb *iocb, struct iov_iter *from)
   │  struct socket *sock = file->private_data;
   ▼  sock_sendmsg(sock, &msg)
net/socket.c: sock_sendmsg() → sock_sendmsg_nosec() → security_socket_sendmsg()
   │
   ▼  sock->ops->sendmsg(sock, msg, size)      ← proto_ops（地址族层）
AF_INET: inet_sendmsg()  (net/ipv4/af_inet.c)
   │  sk = sock->sk;  return sk->sk_prot->sendmsg(sk, msg, size);
   ▼  sk->sk_prot->sendmsg(...)                 ← proto（传输层）
TCP: tcp_sendmsg()   UDP: udp_sendmsg()
```

**关键对应**：`file->private_data = sock`（`sock_alloc_file()` 里设置），
`file->f_op = &socket_file_ops`，`sock->file = file`，`sock->sk = sk`，
而 `sk->sk_socket = sock`（`sock_init_data()` 里双向绑定）。
所以从任意一端都能走通全链路。

### 3.2 `socket()` 的分配链

```
__sys_socket()                       net/socket.c
 ├─ sock_create(family, type, protocol, &sock)
 │   ├─ security_socket_create()
 │   ├─ sock_alloc()                 → 分配 struct socket（sock_inode_cache），
 │   │                                 创建匿名 inode，挂 socket_file_ops
 │   └─ __sock_create()              → net_families[family]->create()
 │        └─ inet_create()           net/ipv4/af_inet.c
 │             ├─ inetsw 查表选 proto/ops（SOCK_STREAM→tcp_prot）
 │             ├─ sk_alloc(net, PF_INET, GFP_KERNEL, answer_prot, kern)
 │             │     → sk_prot_alloc() 从 proto->slab 或 kmalloc 分配控制块
 │             │       （TCP 用 tcp_prot.slab，UDP 用 udp_prot.slab）
 │             │     → sock_lock_init / sk_prot 绑定
 │             ├─ sock_init_data(sock, sk)   net/core/sock.c ★
 │             │     ├─ sk->sk_socket = sock, sock->sk = sk
 │             │     ├─ sk->sk_wq = &sock->wq（若 sock 非空）
 │             │     ├─ sk->sk_data_ready = sock_def_readable
 │             │     ├─ sk->sk_write_space = sock_def_write_space
 │             │     ├─ sk->sk_state_change = sock_def_wakeup
 │             │     ├─ sk->sk_error_report = sock_def_error_report
 │             │     ├─ sk->sk_rcvbuf / sk_sndbuf 初始化（默认值 + 自动调优区间）
 │             │     ├─ sk->sk_rcvtimeo/sk_sndtimeo 初始化（MAX_SCHEDULE_TIMEOUT）
 │             │     └─ skb_queue_head_init(&sk->sk_receive_queue) 等
 │             ├─ inet_init_sock() → sk->sk_prot->init(sk)
 │             │     TCP: tcp_v4_init_sock()/tcp_init_sock()  net/ipv4/tcp.c
 │             │     （设置 snd_cwnd=TCP_INIT_CWND(10)、rto、timestamps、
 │             │       sk_sndbuf 取 tcp_wmem[1]、sk_rcvbuf 取 tcp_rmem[1] 等）
 │             └─ sock->ops = answer->ops;  sock->type = type;
 └─ sock_map_fd(sock, flags)         → 取一个 fd，关联 file
```

`proto->slab` 的意义：`sk_alloc()` 优先用 `prot->slab`（每协议一个 kmem_cache），
避免所有协议的控制块挤在通用 kmalloc 的 size class 里，提升 cache 局部性。
`/proc/slabinfo` 里的 `TCP`、`UDP`、`tw_sock_TCP`、`request_sock_TCP` 就是它们。

### 3.3 `bind()` 与端口分配

```
__sys_bind() → sockfd_lookup_light() → sock->ops->bind → inet_bind()  net/ipv4/af_inet.c
  └─ inet_bind_sk()/__inet_bind()
       ├─ 权限检查：端口 < 1024 需要 CAP_NET_BIND_SERVICE（非 root 会 EACCES）
       │     —— 本教程的 lab 因此全部使用 >= 1024 的端口或让内核临时分配
       ├─ sk->sk_reuse / sk_reuseport 已由 setsockopt 写好，参与冲突判定
       └─ sk->sk_prot->get_port(sk, snum)
            TCP: tcp_v4_get_port() → inet_csk_get_port()
                 net/ipv4/inet_connection_sock.c
                 ├─ inet_csk_bind_conflict()  ← ★ REUSEADDR/REUSEPORT 的判断在这里
                 │     net/ipv4/inet_connection_sock.c
                 └─ inet_bind_hash()/inet_bhash2_update_saddr()
                      把 sk 挂进 inet_hashinfo.bhash（按端口）与 bhash2（按端口+地址）
```

`connect()` 时若未 `bind()`，内核也会走同一个 `inet_csk_get_port()`，
但此时端口来自**临时端口分配**：

```
tcp_v4_connect()  net/ipv4/tcp_ipv4.c
  ├─ 路由查找：ip_route_connect() → 得到源地址
  ├─ 若 sk->sk_num == 0（没 bind 过端口）
  │   └─ inet_hash_connect(&tcp_death_row, sk)
  │        net/ipv4/inet_hashtables.c → __inet_hash_connect()
  │        ├─ 端口范围取自 net.ipv4.ip_local_port_range（本机 32768 60999）
  │        ├─ 对每个候选端口检查 ehash 是否已有同四元组
  │        └─ 若唯一冲突是 TIME_WAIT，且 net.ipv4.tcp_tw_reuse 允许，则复用该端口
  ├─ tcp_connect(): 分配 skb、填写 TCP 头（SYN）、tcp_transmit_skb()
  └─ inet_hash_insert() → 把 sk 挂进 ehash，状态置 TCP_SYN_SENT
```

`bind_conflict` 的判定逻辑（`inet_csk_bind_conflict()`）大致是：
若两个 `sk` 的 `(sk_rcv_saddr, sk_num)` 冲突，则只有当**双方**都允许复用时才放过；
允许复用需要满足 `sk_reuse` 相关条件，或者（对 REUSEPORT）双方都是非特权 uid 且
都设置了 `sk_reuseport`。TIME_WAIT 的 socket 则以 `inet_timewait_sock` 形式存在于
ehash 中，由 `inet_csk_bind_conflict()` 特判。

### 3.4 发送路径：`sendmsg` → `sk_buff`

```
TCP: tcp_sendmsg(struct sock *sk, struct msghdr *msg, size_t size)  net/ipv4/tcp.c
  ├─ lock_sock(sk)
  └─ tcp_sendmsg_locked()                     net/ipv4/tcp.c
       ├─ tcp_send_mss() → tcp_current_mss()：算 MSS（考虑 PMTU、TSO、SACK）
       ├─ for (;;) 循环切片：
       │   ├─ tcp_stream_memory_free() / sk_stream_memory_free()：检查 sk_sndbuf
       │   │     需不需要等待（等待时设置 SOCK_NOSPACE，并等 sk_stream_wait_memory）
       │   ├─ 复用当前 skb（tcp_skb_append 之前先看 can_coalesce / 尾包空间）
       │   │     否则 tcp_stream_alloc_skb() 拿一个新 skb
       │   ├─ skb_add_data()（线性区）或 skb_zerocopy_iter_stream()/copy_from_iter（frags）
       │   │     ├─ 小数据 → 拷进 skb 线性区（skb_put，一次 memcpy）
       │   │     └─ 否则 skb_can_coalesce()+skb_fill_page_desc()
       │   │           把**用户页**挂到 skb_shared_info.frags[]（零拷贝到 frags）
       │   └─ 记账：sk_mem_charge(sk, skb->truesize)、sk_wmem_queued += ...
       ├─ tcp_push() / __tcp_push_pending_frames()
       │     └─ tcp_write_xmit()  net/ipv4/tcp_output.c
       │          ├─ tcp_cwnd_test()：cwnd 允许发多少
       │          ├─ tcp_nagle_test() / tcp_nagle_check()：Nagle 判定（见 §6）
       │          ├─ tcp_tso_should_defer()：TSO 推迟
       │          └─ tcp_transmit_skb() → icsk->icsk_af_ops->queue_xmit
       │                = ip_queue_xmit()（IPv4）→ 进入 IP 层
       └─ tcp_check_probe_timer() / sk->sk_write_space 回调
```

要点辨析：

- **数据拷贝次数（普通 `send`）**：用户缓冲 → skb 线性区/frags，共 **1 次 CPU 拷贝**；
  之后走 qdisc/驱动时，若网卡支持 SG，则 frags 直接 DMA，不再拷贝。
- **`sk_sndbuf` 限制的是 `sk_wmem_queued`（已入队未确认的字节 + truesize）**，
  不是单次 `send()` 的长度。单次 `send()` 可以远大于 `sk_sndbuf`：
  内核会切片并在缓冲区满时睡眠（阻塞 socket）或返回部分写入。
- **MSS 与 TSO**：`tcp_current_mss()` 给出的 MSS 只用于 TCP 序号推进与 cwnd 计算；
  实际发到网卡的 skb 可能因为 TSO 而包含多个 MSS 的载荷（`tp->gso_segs`）。

### 3.5 接收路径：skb → `recvmsg` → 用户态

```
软中断/NAPI:  ip_rcv → ip_local_deliver → 四层分发
   ▼
tcp_v4_rcv(struct sk_buff *skb)          net/ipv4/tcp_ipv4.c
  ├─ __inet_lookup_skb(..., &refcounted)  net/ipv4/inet_hashtables.c
  │     └─ __inet_lookup()：先查 ehash（精确四元组），再查 lhash2（监听者）
  ├─ 若 sk 处于 TCP_TIME_WAIT → tcp_timewait_state_process()（轻量路径，无 struct sock 全量）
  ├─ 若 sk->sk_state == TCP_LISTEN → tcp_v4_do_rcv() → tcp_rcv_state_process() → tcp_conn_request()
  └─ 否则 nf_hook → tcp_v4_do_rcv(sk, skb)  net/ipv4/tcp_ipv4.c
        ├─ 若 socket 被用户态锁住 → tcp_add_backlog()/sk_add_backlog()
        │      （net/ipv4/tcp_ipv4.c: tcp_add_backlog() 有长度合并优化）
        ├─ tcp_rcv_established()  net/ipv4/tcp_input.c（快路径 + 慢路径）
        │     ├─ 快路径（header prediction）：直接 tcp_queue_rcv()、
        │     │    tcp_ack()、tcp_data_ready()
        │     └─ 慢路径 → tcp_data_queue() → tcp_ofo_queue()（乱序）→ tcp_sack()
        └─ tcp_data_ready(sk)  →  sk->sk_data_ready(sk)
                                     默认是 sock_def_readable()  net/core/sock.c
                                       └─ wake_up_interruptible_sync_poll(&sk->sk_wq->wait, ...)
                                             └─ ep_poll_callback()  fs/eventpoll.c
                                                   把 epitem 挂进 rdllist，唤醒 epoll_wait

用户态:  recv()/read()
   ▼  sock_read_iter → sock_recvmsg → sock->ops->recvmsg
AF_INET: inet_recvmsg() → sk->sk_prot->recvmsg
TCP: tcp_recvmsg()  net/ipv4/tcp.c
  ├─ 从 sk_receive_queue 取 skb（skb_peek / skb_copy_datagram_msg）
  ├─ 乱序/空洞处理：tcp_recvmsg_locked() 里遇到 ofo 队列会先尝试 tcp_collapse
  ├─ 更新 tp->copied_seq
  └─ tcp_cleanup_rbuf(sk, copied) → __tcp_cleanup_rbuf()
        ├─ sk_mem_uncharge(sk, ...) / sk_mem_reclaim(sk)
        ├─ tcp_rcv_space_adjust()：接收缓冲自动调优（tcp_moderate_rcvbuf）
        └─ 若窗口可以扩大 → tcp_send_ack()/tcp_send_window_probe()
UDP: udp_recvmsg()  net/ipv4/udp.c
  ├─ skb_recv_datagram(sk, flags, ...) 从 udp_sk(sk)->reader_queue 或 sk_receive_queue 取
  └─ skb_copy_datagram_msg()（= skb_copy_datagram_iter() 的 msghdr 包装）
```

`sk_data_ready` 是一条**函数指针回调链**，这是本章最值得记住的设计：
内核在数据入队后只调用 `sk->sk_data_ready(sk)`，完全不需要知道上层是 epoll、
select、还是阻塞 `recv`。协议栈与 I/O 多路复用因此彻底解耦。

### 3.6 epoll 唤醒链（把 §3.5 的最后一步展开）

```
数据到达 → tcp_data_ready(sk)
   ▼
sock_def_readable(sk)                      net/core/sock.c
   ├─ wq = rcu_dereference(sk->sk_wq);    /* == &sock->wq */
   ├─ wake_up_interruptible_sync_poll(&wq->wait, EPOLLIN | EPOLLPRI | EPOLLRDNORM | EPOLLRDBAND)
   └─ 若 wq->fasync_list 非空 → kill_fasync()（SIGIO 支持）
   ▼
__wake_up_common() 遍历等待队列项 → 调用每个 wait_queue_entry 的 func
   ▼
ep_poll_callback(wait, mode, sync, key)    fs/eventpoll.c
   ├─ epq.epi->event.events & key  是否匹配（不匹配直接返回）
   ├─ 加锁把 epitem 链入 ep->rdllist
   └─ wake_up(&ep->wq) 唤醒正在 epoll_wait 的进程
```

`epoll_ctl(EPOLL_CTL_ADD)` 时，`ep_insert()` 会把
`eppoll_entry->wait.func = ep_poll_callback` 注册到 `sk->sk_wq->wait`。
所以「TCP 数据到达 → epoll_wait 返回」这条链**没有轮询**，是纯回调。

LT 与 ET 的差别不在内核唤醒，而在 `ep_send_events()` 是否在每次 `epoll_wait`
时重新检查「仍然就绪」的条件：LT 会重复上报，ET 只在就绪状态**变化**时上报一次
（内核通过 `epitem->event.events` 与 `ep_poll_safewake` 等机制保证边沿语义）。
因此 ET 模式下用户必须循环读到 `EAGAIN`，否则残留数据不会再有新事件——
这正是 `labs/01-socket-api-basics/tcp_echo_server.c` 里 `--trigger et` 想演示的陷阱。

### 3.7 `sk_add_backlog`：为什么会有 backlog 队列

`tcp_v4_rcv()` 在进入 `tcp_v4_do_rcv()` 之前会尝试获取 socket 锁；
如果拿不到（用户态正在同一个 socket 上做 `recvmsg`/`setsockopt` 等长操作），
内核**不阻塞软中断**，而是把 skb 挂到 `sk->sk_backlog` 链表里，等锁持有者释放时再处理：

```
tcp_v4_rcv()  net/ipv4/tcp_ipv4.c
  ├─ bh_lock_sock_nested(sk)
  ├─ if (!sock_owned_by_user(sk))：ret = tcp_v4_do_rcv(sk, skb)
  └─ else if (tcp_add_backlog(sk, skb, &drop_reason))：goto discard_and_relse
        └─ sk_add_backlog(sk, skb, sk->sk_rcvbuf)   include/net/sock.h
             ├─ sk_rcvqueues_full(sk, limit)：用
             │     sk->sk_backlog.len + atomic_read(&sk->sk_rmem_alloc) > limit
             │     判满，满则 -ENOBUFS（对应 /proc/net/netstat 的 TCPBacklogDrop）
             └─ __sk_add_backlog(sk, skb)：尾插链表并累加 sk_backlog.len
  稍后 release_sock() → __release_sock() 逐条取出来重新走 tcp_v4_do_rcv()
        net/core/sock.c
```

这也是为什么「为了看内核处理而长时间持锁」是反模式：backlog 变长、丢包计数上涨。

## 6. 常见陷阱、调优旋钮、面试/自测题

### 6.1 陷阱与调优

1. **`SO_SNDBUF`/`SO_RCVBUF` 的加倍语义**。`setsockopt(SO_SNDBUF, 65536)` 之后
   `getsockopt` 会读出 131072。内核在 `sock_setsockopt()` 中把用户值存入
   `sk_sndbuf/sk_rcvbuf` 时乘 2（并做上下限 clamp），回读时除 2。
   真实可用的发送/接收数据量要看 `ss -tme` 的 `skmem` 明细或 `/proc/net/tcp`。
2. **显式设置缓冲区会关闭自动调优**。`setsockopt` 会置 `SOCK_RCVBUF_LOCK`
   （`sk_userlocks` 位），TCP 就不再依据带宽时延积增长 `sk_rcvbuf`。
   长肥管道（BDP 大）上手动设小 `SO_RCVBUF` 是吞吐杀手。
3. **`sk_sndbuf` 与单次 `send()` 长度无关**。大 `send()` 会被切片并在
   `sk_wmem_queued` 逼近 `sk_sndbuf` 时阻塞/部分写。
4. **LT 与 ET 混用会踩「数据不再上报」**。ET 下必须循环读到 `EAGAIN`。
5. **`SO_REUSEADDR` 不等于 `SO_REUSEPORT`**。前者解决 TIME_WAIT 重绑与
   通配/具体地址共存，后者才是「多进程同端口负载均衡」。
   UDP 与 TCP 的复用语义也不完全相同（UDP 多播地址另有规则）。
6. **`accept()` 之前连接已在队列里**。握手由内核完成，`accept()` 只是从
   `icsk_accept_queue` 摘取；应用来不及 `accept()` 会导致全连接队列溢出。
7. **`recv` 返回 0 只代表 FIN**，不代表出错；错误要通过 `errno` 或 `SO_ERROR` 拿。
8. **`sk_data_ready` 可被替换**。TCP 在某些路径会把 `sk_data_ready` 换成
   私有实现（如 `tcp_ulp`/`smc`、`kcm`），排查 epoll 不唤醒时要想到这一点。
9. **`sk_backlog` 不是「连接积压队列」**。名字容易混淆：它指
   **单个已连接 socket 内部**因抢不到 socket 锁而暂存的 skb 链表；
   而 `icsk_accept_queue` 才是「等待 accept 的连接」。
10. **`MSG_ZEROCOPY` 只对「大于一定阈值」的发送有效**，
    且需要用户处理 `SO_EE_ORIGIN_ZEROCOPY` 错误队列通知，否则缓冲区不可复用。

## 7. 本章小结 + 延伸阅读

### 小结

- 内核用 `struct socket`（协议无关门面）+ `struct sock`（协议控制块）双层抽象，
  通过 `file->private_data`、`sock->sk`、`sk->sk_socket` 四通八达地互相引用。
- `inet_family_ops.create → inet_create()` 从 `inetsw[]` 选出
  `inet_stream_ops + tcp_prot` 或 `inet_dgram_ops + udp_prot`；
  `sk_alloc()` 负责控制块内存，`sock_init_data()` 负责把回调、队列、缓冲区、
  `sk_wq` 与 `struct socket` 绑好。
- 发送路径 `sendmsg → tcp_sendmsg_locked → tcp_write_xmit → tcp_transmit_skb →
  ip_queue_xmit`，接收路径 `tcp_v4_rcv → tcp_v4_do_rcv → tcp_rcv_established →
  tcp_data_queue → sk_data_ready`。
- 内存记账通过 `sk_mem_charge/sk_mem_uncharge` 操作 `sk_forward_alloc`，
  限额判定在 `__sk_mem_schedule()`，汇总值可从 `/proc/net/sockstat`、
  `/proc/net/protocols`、`ss -tme` 读出来。
- I/O 多路复用的本质是 `sk_data_ready`/`sk_write_space` 回调 +
  `sk_wq` 等待队列 + `ep_poll_callback`，不是轮询。
